# Matriz de verificación y despliegue (implement-task)

Se aplica **por superficie**: si la tarea toca varias, se suman las filas. El porqué de cada
regla está en `INVARIANTS.md` y `AGENTS.md`.

## Comprobaciones (paso 6, las corre `task-verifier`)

| Superficie                               | Comprobaciones                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Siempre**                              | `npm run check` (tipos + lint + formato + tests) y `npm run check:secrets`. Si solo falla el formato: `npx prettier --list-different .` para ver qué archivo es.                                                                                                                                                                                                                                                                                                                                                                              |
| **Migración** (`supabase/migrations/**`) | Solo archivos **nuevos** (`git diff --name-status main -- supabase/migrations` sin `M`). Fecha del archivo posterior a la última. RLS activado, 4 policies (o las que toquen) `to authenticated` con `(select auth.uid())`, GRANTs y `revoke all … from anon`. FK a `auth.users` con `on delete cascade` si son datos de usuario. Aplicada en la base de desarrollo y `src/types/database.ts` regenerado (`npm run db:types`, sin diff pendiente). `npm run check:rls` si hay base local; si no, lo hará el CI en el PR (dilo en el informe). |
| **Datos compartidos entre usuarios**     | Prueba con dos cuentas: B no ve ni toca lo de A salvo lo que la regla permite. Revisión con `anti-hackeo` (modo cambio).                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Edge Function**                        | `verify_jwt` en `supabase/config.toml` coherente (`true` salvo webhooks externos con firma). Usuario sacado del token, no del body. Entrada validada. Secretos por `Deno.env.get`, nunca en el código. Desplegada en desarrollo (`npx supabase functions deploy <nombre> --use-api`) y probada desde la app o el Dashboard.                                                                                                                                                                                                                   |
| **App (JS)**                             | Pantallas sin imports de Supabase (lint). Colores del tema (sin hex en `src/app`/`src/components`). 4 estados en pantallas con datos. `queryKeys` nuevas si cambia la forma de los datos. Textos en castellano.                                                                                                                                                                                                                                                                                                                               |
| **Dependencia nueva**                    | Instalada con `npx expo install`. ¿Tiene código nativo? Si sí → la tarea es compleja y Expo Go deja de valer (debe estar aprobado en G3).                                                                                                                                                                                                                                                                                                                                                                                                     |
| **UI visible**                           | Autocomprobación en web (`npm start` → `w`) con capturas antes de pedir la prueba en el móvil (paso 7).                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Despliegue (paso 10, orden estricto)

1. **Migración** — en desarrollo ya se aplicó en el paso 5 (`npm run db:push`, con OK). Si hay
   proyecto de **producción**: solo por PR + workflow `deploy-supabase.yml`, con el CI en verde.
   Nunca `db push` a mano contra producción.
2. **Tipos** — `npm run db:types` y commit si cambian.
3. **Edge Functions** — desarrollo: `npx supabase functions deploy <nombre> --use-api`, una a
   una y por nombre. Producción: por el workflow al mergear.
4. **App** — sin publicar: basta con el merge (el dueño la ve con `npm start`). Publicada: cambios
   solo JS → `/actualizar-ota`; nativos → `/publicar`.
5. **Comprobación final** — lo que demuestre que funciona: el dueño lo ve en su móvil (con la app
   publicada, tras abrirla dos veces si fue OTA), Supabase → Logs sin errores nuevos, Sentry sin
   errores nuevos si está conectado.
